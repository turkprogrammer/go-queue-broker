# Queue Broker

FIFO очередь сообщений поверх HTTP — только stdlib.

## Запуск

### Linux / macOS

```bash
go run main.go 8080

# или собрать:
go build -o main main.go
./main 8080
```

### Windows (PowerShell)

```powershell
go run main.go 8080

# или собрать:
go build -o main.exe main.go
.\main.exe 8080
```

## API

| Метод | URL | Описание |
|-------|-----|----------|
| PUT | `/queue?v=message` | Положить сообщение в очередь |
| GET | `/queue` | Забрать сообщение (FIFO) |
| GET | `/queue?timeout=N` | Забрать с ожиданием N секунд |

## Коды ответа

- `200` — успех, пустое тело (PUT) или сообщение (GET)
- `400` — отсутствует параметр `v` (PUT) или неверный timeout (GET)
- `404` — очередь пуста / истёк таймаут (GET)
- `405` — неподдерживаемый метод

## Примеры

### Linux / macOS

```bash
# PUT
curl -X PUT "http://127.0.0.1:8080/pet?v=cat"
curl -X PUT "http://127.0.0.1:8080/pet?v=dog"
curl -X PUT "http://127.0.0.1:8080/role?v=manager"

# GET (FIFO)
curl "http://127.0.0.1:8080/pet"     # → cat
curl "http://127.0.0.1:8080/pet"     # → dog
curl "http://127.0.0.1:8080/pet"     # → 404

# GET с ожиданием
curl "http://127.0.0.1:8080/pet?timeout=5"

# Ошибки
curl -X PUT "http://127.0.0.1:8080/test"           # → 400
curl "http://127.0.0.1:8080/empty"                 # → 404
```

### Windows (PowerShell)

```powershell
# PUT
curl.exe -X PUT "http://127.0.0.1:8080/pet?v=cat"
curl.exe -X PUT "http://127.0.0.1:8080/pet?v=dog"
curl.exe -X PUT "http://127.0.0.1:8080/role?v=manager"

# GET (FIFO)
curl.exe "http://127.0.0.1:8080/pet"     # → cat
curl.exe "http://127.0.0.1:8080/pet"     # → dog
curl.exe "http://127.0.0.1:8080/pet"     # → 404

# GET с ожиданием
curl.exe "http://127.0.0.1:8080/pet?timeout=5"

# Ошибки
curl.exe -X PUT "http://127.0.0.1:8080/test"       # → 400

```

## Особенности реализации

- FIFO порядок сообщений и ожидающих читателей
- Множественные именованные очереди (lazy-инициализация)
- Блокирующее чтение с таймаутом (long-poll) — без серверных таймаутов,
  чтобы ожидание работало на любой `timeout=N`
- Нет внешних зависимостей (только stdlib)
- Race-condition safe (мьютексы) + drain канала при таймауте/отмене
  (сообщение, отправленное в момент истечения таймаута, не теряется)
- 160 строк кода

## Результаты тестов

Проверено вручную на запущенном сервере. Статические проверки:
`go build`, `go vet`, `gofmt -l` — без замечаний.

### Сценарии из ТЗ

| Запрос | Ожидание | Факт |
|--------|----------|------|
| `PUT /pet?v=cat` / `?v=dog` | `200` (пустое тело) | `200` ✅ |
| `GET /pet` ×4 | `cat`, `dog`, `404`, `404` | `cat`, `dog`, `404`, `404` ✅ |
| `PUT /role?v=manager` / `?v=executive` | `200` | `200` ✅ |
| `GET /role` ×3 | `manager`, `executive`, `404` | `manager`, `executive`, `404` ✅ |

### Long-poll

| Запрос | Ожидание | Факт |
|--------|----------|------|
| `GET /lp?timeout=10`, через ~2с `PUT ?v=late` | дожидается, тело `late` | тело `late` ✅ |
| `GET /empty?timeout=3` (без PUT) | ~3с ожидания, `404` | `404` ✅ |

### FIFO получателей

Два получателя стартуют с `timeout=10` один за другим (A раньше B),
затем кладутся `v=1` и `v=2`. Первым должен получить тот, кто первый
запросил.

| Получатель | Ожидание | Факт |
|------------|----------|------|
| A (первый запросивший) | `1` | `1` ✅ |
| B (второй запросивший) | `2` | `2` ✅ |

### Крайние случаи

| Запрос | Ожидание | Факт |
|--------|----------|------|
| `PUT /x` (без `v`) | `400` | `400` ✅ |
| `PUT /x?v=` (пустое `v`) | `200` | `200` ✅ |
| `GET /x?timeout=-1` | `400` | `400` ✅ |
| `GET /x?timeout=abc` | `400` | `400` ✅ |
| `GET /emptyzero?timeout=0` (пустая очередь) | `404` (без ожидания) | `404` ✅ |
| `POST /x` / `DELETE /x` | `405` | `405` ✅ |
| `GET /` (пустой путь) | `400` | `400` ✅ |
| запуск без аргумента порта / с лишним | `exit 1` | `exit 1` ✅ |
